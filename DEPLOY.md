# Размещение Psy Method App на Render

## Почему Render

Для текущего проекта рекомендую **Render: Node.js Web Service + managed PostgreSQL** при условии, что подходят зарубежное размещение и способ оплаты. Это React/Vite + Express + PostgreSQL без загрузок на диск и фоновых обработчиков. Один сервис обслуживает сайт и API, сессии сохраняются в БД между перезапусками.

| Вариант | Оценка для проекта |
| --- | --- |
| Render | Рекомендую для старта: декларативная конфигурация уже в репозитории, управляемая БД, TLS, автоматический деплой |
| Railway | Также подходит; Hobby от $5/месяц с включённым расходом на эту сумму, итог зависит от потребления приложения и БД |
| VPS | Подходит при обязательном размещении в конкретной стране; обновления ОС, TLS, PostgreSQL и резервные копии нужно обслуживать самостоятельно |

Ориентир на 20.09.2026: web **$7/месяц**, БД **$6/месяц**, диск 5 GB × $0.30 = **$1.50/месяц**. Итого около **$14.50/месяц** при бесплатном тарифе workspace и небольшой нагрузке, без налогов, домена и превышения включённых лимитов. Перед созданием сверьте итог в панели: [тарифы Render](https://render.com/pricing), [названия планов](https://render.com/docs/compute-plans), [тарифы Railway](https://docs.railway.com/pricing/plans).

## Рекомендуемая схема

Приложение размещается в регионе Frankfurt как один постоянно работающий Node.js Web Service и отдельная управляемая PostgreSQL. Express одновременно обслуживает API и собранный React-клиент, поэтому отдельный хостинг фронтенда и междоменные cookies не нужны.

Файл `render.yaml` создаёт минимальную production-конфигурацию: web-сервис 0.5 CPU / 512 MB, PostgreSQL 0.1 CPU / 256 MB с диском 5 GB, приватное подключение к БД, автоматический TLS, health check и автодеплой.

> Не переводите PostgreSQL на план Free для рабочих данных: бесплатная БД Render истекает через 30 дней, после льготного периода удаляется и не имеет управляемых резервных копий. Бесплатный web-сервис также засыпает после 15 минут простоя. Ограничения описаны в [документации бесплатных планов](https://render.com/docs/free). Текущий Blueprint рассчитан на платную БД; для Free недостаточно просто поменять plan, поскольку у неё другие ограничения диска.

## Перед размещением

1. Создайте закрытый или открытый репозиторий GitHub и отправьте в него проект. Убедитесь, что `server/.env` не попал в commit.
2. Придумайте отдельные production-учётные данные суперадминистратора. Пароль желательно сгенерировать менеджером паролей (не менее 20 случайных символов).
3. Установите локально Node.js из `.node-version`, выполните `npm run deploy:build`. В Git должны попасть корневой, клиентский и серверный `package-lock.json`, исходники и `render.yaml`; `node_modules`, `dist` и `.env` отправлять не нужно.
4. Создайте аккаунт Render и добавьте способ оплаты. Конфигурация по умолчанию использует платные ресурсы.

## Первый деплой

1. В Render откройте **New → Blueprint**.
2. Подключите GitHub и выберите репозиторий проекта.
3. Render обнаружит корневой `render.yaml`. Выберите нужную ветку; Root Directory оставьте пустым (корень репозитория). Проверьте регион и стоимость ресурсов.
4. В форме секретов заполните:
   - `SUPER_ADMIN_USERNAME` — логин суперадминистратора;
   - `SUPER_ADMIN_PASSWORD` — его сильный уникальный пароль.
5. Нажмите **Apply / Deploy Blueprint**, затем дождитесь, пока база и web-сервис получат статус **Live**. Первый запуск сам создаст таблицы и учётную запись суперадминистратора.
6. Откройте адрес `https://psy-method-app.onrender.com` (точный адрес показан в карточке сервиса) и проверьте:
   - `/api/health` возвращает `{"ok":true}`;
   - вход суперадминистратора на `/super-admin/login`;
   - перезагрузку страницы `/super-admin/login` по прямому адресу;
   - создание администратора;
   - создание и прохождение всех 10 шагов по новой тестовой ссылке (ссылка `demo-token` на главной не создаёт участника);
   - выгрузку результатов.

Последующие push в подключённую ветку автоматически запускают сборку и деплой. Если сборка не проходит, Render оставляет предыдущую рабочую версию.

## Переменные окружения

| Переменная | Значение / источник |
| --- | --- |
| `NODE_ENV` | `production`, задано в Blueprint; включает Secure cookies |
| `PORT` | Назначает Render, вручную не задавайте |
| `DATABASE_URL` | Приватный адрес созданной БД, Blueprint подставляет автоматически |
| `COOKIE_SECRET` | Blueprint генерирует автоматически |
| `SUPER_ADMIN_USERNAME`, `SUPER_ADMIN_PASSWORD` | Вводятся при создании; пароль не попадает в Git |
| `CLIENT_URL` | Только для собственного домена: HTTPS origin без пути и завершающего `/` |
| `RENDER_EXTERNAL_URL` | Системная переменная Render, используется при отсутствии `CLIENT_URL` |

`VITE_API_BASE_URL` не задавайте: в production клиент обращается к `/api` на том же домене. Версия Node берётся из `.node-version`; не оставляйте в панели старый `NODE_VERSION`, у него более высокий приоритет. Сборка явно устанавливает devDependencies, необходимые TypeScript и Vite, даже при `NODE_ENV=production`.

## Собственный домен

1. В web-сервисе откройте **Settings → Custom Domains → Add Custom Domain**.
2. Добавьте DNS-записи, которые покажет Render, и дождитесь выпуска TLS-сертификата.
3. В **Environment** добавьте `CLIENT_URL=https://ваш-домен` и выполните redeploy. Без собственного домена переменная не нужна: приложение использует системный `RENDER_EXTERNAL_URL`.

## Эксплуатация и восстановление

- Следите за журналом web-сервиса и метриками PostgreSQL в Render.
- Не храните пользовательские данные в файловой системе сервиса: она временная. Текущая версия приложения хранит результаты в PostgreSQL и этому требованию соответствует.
- Перед изменением структуры таблиц создавайте логический экспорт БД в панели Render и сохраняйте копию вне сервиса. Текущая инициализация безопасно создаёт отсутствующие таблицы, но не заменяет систему версионированных миграций.
- При компрометации пароля смените `SUPER_ADMIN_PASSWORD`. Учтите: текущий bootstrap не обновляет пароль существующей записи автоматически; для ротации потребуется отдельная команда или изменение записи в БД.

## Откат и восстановление

При ошибке приложения выберите предыдущий успешный deploy в панели web-сервиса и выполните rollback. Откат кода не откатывает содержимое базы.

При повреждении данных используйте Recovery в карточке PostgreSQL: восстановите БД в новый экземпляр на нужный момент, проверьте таблицы и результаты, затем переключите `DATABASE_URL` web-сервиса на внутренний адрес восстановленной БД и выполните redeploy. Обновите ссылку `fromDatabase` в Blueprint под новое имя БД, чтобы следующий sync не вернул старое подключение. Исходную БД сохраняйте до проверки восстановления. Доступность периода восстановления и порядок экспорта описаны в [документации резервных копий](https://render.com/docs/postgresql-backups).

`ipAllowList: []` закрывает внешний доступ к БД. Для разового переноса локальных данных через внешний адрес временно разрешите только свой IP `/32`, используйте `pg_dump` / `pg_restore` подходящей версии и после переноса удалите разрешение. Первый deploy создаёт пустую БД, существующие локальные данные автоматически не копируются.

## Если запуск не удался

- `Missing env variable`: проверьте Environment, особенно оба секрета суперадминистратора.
- Ошибка подключения к БД / health check 503: проверьте готовность БД, совпадение региона и внутренний `DATABASE_URL`. SSL для приватной БД Render уже включён в коде с учётом её self-signed сертификата.
- Не найдены `tsc` / `vite`: build command должен быть `npm run deploy:build`.
- `Client build missing`: запускайте полную сборку из корня, а не только сборку сервера.
- Вход не сохраняется: откройте HTTPS-адрес, проверьте `CLIENT_URL` и отсутствие лишнего `VITE_API_BASE_URL`.
- Замена `SUPER_ADMIN_PASSWORD` не меняет пароль уже существующего пользователя: bootstrap создаёт только отсутствующую запись. Не рассчитывайте на redeploy как на ротацию пароля.

## Локальная проверка сборки

```sh
npm run deploy:build
```

Для локального запуска скопируйте `server/.env.example` в `server/.env`, заполните его и подготовьте доступную PostgreSQL. Оставьте `NODE_ENV=development` для локального HTTP и БД без TLS, а `CLIENT_URL` задайте `http://localhost:3001`:

```sh
npm --prefix server run start
```

Откройте `http://localhost:3001`. Это проверка собранного приложения; TLS, Secure cookies и приватное подключение Render проверяются после размещения.
